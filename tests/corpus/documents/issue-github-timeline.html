PDF totals are rounded per line instead of per document #1187

kmeier commented Oct 28, 2025

When an invoice has many lines with 19 % VAT, the VAT in the PDF differs by a few cents from the one in the XML (ZUGFeRD). The PDF rounds the VAT of each line and adds them up; EN 16931 wants the VAT of the sum per rate (BR-CO-17).

Steps to reproduce

  1. Create an invoice with 7 lines of 0,99 € at 19 %
  2. Render the PDF with invoicer render --zugferd
  3. Compare TaxTotalAmount in the XML with the total in the PDF
WhereNetVATGross
PDF6,931,338,26
XML6,931,328,25

Warning

Validators (KoSIT) reject these invoices, so customers in the public sector cannot pay them.

Thanks @kmeier, confirmed. It comes from TotalsCalculator::vat(); the fix is to group by rate first. Related: #1042.

Suggested change
return array_sum(array_map(fn ($line) => round($line->vat(), 2), $this->lines));
return array_sum(array_map(fn ($group) => round($group->net() * $group->rate, 2), $this->byRate()));
