Deploying the import service

The import service reads supplier price lists from an SFTP drop, validates them against the catalogue schema and writes the accepted rows to the pricing database. This guide covers a production deployment with Docker Compose on a single host. Allow about 30 minutes; you need SSH access to the host and the credentials listed in Prerequisites.

Note

From version 4.2 the service no longer polls the drop folder. It is triggered by the scheduler instead, so a host that only runs the importer needs no cron entry.

Prerequisites

  • Docker Engine 27 or later with the Compose plugin
  • A PostgreSQL 16 database and a role with CREATE on the pricing schema
  • The SFTP host key of the supplier gateway (ask the integration team)

Configuration

Create the file below next to compose.yaml. Lines 4 to 6 are the ones that differ between staging and production:

# importer.env: read once at start-up
IMPORT_DROP=sftp://gateway.example.net/drop/prices
IMPORT_SCHEMA=catalogue-v7.json
DATABASE_URL=postgres://importer@db-prod-02:5432/pricing
IMPORT_BATCH_SIZE=5000
IMPORT_REJECT_THRESHOLD=0.02
LOG_FORMAT=json
TZ=Europe/Berlin

Then start the service in the way that matches your host:

docker compose --env-file importer.env up -d importer
docker compose logs -f importer

sudo systemctl enable --now importer.service
journalctl -u importer -f

kubectl apply -k deploy/overlays/production
kubectl rollout status deployment/importer -n pricing

Do not run two importers against one drop

The importer takes no lock on the SFTP folder. Two instances read the same file twice, and the second run rejects every row as a duplicate. Scale with IMPORT_BATCH_SIZE, not with replicas.

Reject reports

Rows that fail validation are written to a reject report. Each report is a CSV file with one row per rejected line and the reason in the last column:

CodeMeaningTypical cause
E101Unknown article numberThe supplier sent a new article before it was listed
E204Price below the floorA decimal comma read as a thousands separator
E305Currency mismatchPrice list in CHF for a supplier set up in EUR
W410Price change above 30 %Legitimate, but needs a buyer's approval

If more than IMPORT_REJECT_THRESHOLD of a file's rows are rejected, the whole file is rejected and the buyer on call gets an e-mail. Press Ctrl+C to leave the log view without stopping the service.

Re-running a rejected file

Move the file from drop/rejected/ back to drop/prices/ after the supplier has fixed it. The importer keeps a checksum of every file it has accepted1, so an unchanged file is skipped with a notice instead of being imported twice.

Checksums

The checksum is a SHA-256 over the file's bytes after the line endings have been normalised, so a file saved again on Windows is still recognised:

import hashlib

def checksum(path: str) -> str:
    """SHA-256 of a price list with normalised line endings."""
    digest = hashlib.sha256()
    with open(path, "rb") as file:
        for line in file:
            digest.update(line.rstrip(b"\r\n") + b"\n")
    return digest.hexdigest()  # 64 hex digits, stored in import_files.checksum

assert len(checksum("sample.csv")) == 64

A file of 120 000 rows is checked in about 0.4 s on the production host.
