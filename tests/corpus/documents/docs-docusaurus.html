Webhooks

Parcel sends a POST request to your endpoint whenever a shipment changes state. Each request carries one event; retries use the same event.id, so make your handler idempotent.

info

Webhooks are available on the Business plan and above. In the sandbox they are sent to https://hooks.example unless you set an endpoint.

Registering an endpoint​

Create the endpoint in the dashboard under Settings → Webhooks or with the API:

  • cURL
  • Node.js
  • PHP
curl https://api.parcel.example/v3/webhooks \
  -u "sk_live_…:" \
  -d url=https://shop.example/hooks/parcel \
  -d "events[]=shipment.delivered" -d "events[]=shipment.exception"

Verifying signatures​

Every request has a Parcel-Signature header: a timestamp and an HMAC-SHA256 of timestamp.body with your endpoint secret. Reject requests older than five minutes.

server/verify.js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(header, body, secret) {
  const [t, v1] = header.split(',').map(p => p.slice(2));
  if (Date.now() / 1000 - Number(t) > 300) return false;
  const mac = createHmac('sha256', secret).update(`${t}.${body}`).digest();
  return timingSafeEqual(mac, Buffer.from(v1, 'hex'));
}
Compare the raw body

Frameworks that parse JSON before your handler runs re-serialise it differently. Read the raw bytes, for example with express.raw({ type: 'application/json' }).

Event types​

EventSinceSent when

shipment.out_for_delivery3.2the parcel is on the last vehicle
shipment.delivered3.0the recipient or a neighbour signed, or the parcel was left at a safe place
shipment.exception3.1delivery failed: address unknown, refused, damaged; see exception.code

Retries and ordering

Up to 12 retries over three days.

Events are delivered at least once and not in order. Sort by created if you need the latest state, or fetch the shipment.

Press Ctrl + K in the dashboard to search events by tracking number.
